# 0011 실패는 실패라고 말한다, 데이터 모양은 경계에서 정한다

- 상태: 적용 (2026-10-22, #126 · #127)

## 배경

라운드 3·4가 "하지 않은 것"으로 남긴 것 세 가지.

- 클라이언트 요청 실패(피드·기수 목록·블로그 탭·검색)가 전부 "없습니다" 빈 상태로 보였다. `isError`를 읽는 곳이 없었다 (ADR 0008 알려진 한계)
- 팀 블로그 글의 작성자 DTO에는 `roles`·`tracks`가 없어 화면이 `roles ?? []`로 방어했다. 타입은 필수인데 값은 없을 수 있는 거짓말 (ADR 0006)
- `cohorts()`만 서버 데이터 캐시가 없었다. 네트워크 동작이 바뀌어 미뤘다 (ADR 0006)

## 결정

1. **실패 상태는 빈 상태와 같은 틀, 다른 말** (#126): `shared/ui/ErrorState({ frame, size, onRetry })` — `EmptyState`와 같은 variant에 "불러오지 못했습니다" + "다시 시도"(`buttonVariants secondary`), `role=alert`. 피드(`useFeedPosts`)·기수 목록(`useCohortMembers`, 받은 멤버가 0일 때만)·블로그 탭이 `isError`·`refetch`를 쓰고, 검색은 드롭다운 문구만 "검색에 실패했습니다". 스크린샷 픽스처는 전부 성공 응답이라 화면 0픽셀 — 실패 화면은 vitest가 고정한다(실패 → 다시 시도 → 복구)
2. **DTO 정규화는 API 계층에서 한 번** (#127): `postApi.feed`가 `member.roles/tracks ?? []`를 채운다. 런타임 검증 라이브러리를 들이지 않는 이유는 ADR 0006과 같다(계약 스냅샷이 모양을 고정) — 하지만 "있을 수도 없을 수도"인 필드는 경계에서 한 번 채워 화면이 `??`를 모르게 한다. `RoleBadges`의 `roles`는 필수
3. **기수 목록도 5분 캐시** (#127): `memberApi.cohorts()`에 `serverCache(300)`. 기수는 분기에 한 번 바뀌므로 최대 5분 묵어도 된다. 다른 서버 prefetch(검색·상세·피드)와 같은 정책 — 예외가 하나 사라졌다

## 결과

- 테스트 60 → 61 files, 246 → 251 cases(실패 상태 5건, 정규화 1건, 캐시 1건 — 단, #127은 #126 뒤에 와 합계는 251). 래칫 93/93
- 스크린샷 38장 0픽셀. 스테이징·운영에서 `role=alert`가 정상 응답 때 0개임을 확인

## 하지 않은 것

- 부분 실패(다음 페이지만 실패)는 표시하지 않는다. 첫 페이지가 있으면 목록을 그대로 두고 센티널이 다시 시도한다
- `FeedItem.member`를 별도 `FeedAuthor` 타입으로 나누지 않았다. 정규화 뒤에는 `Member`와 같은 모양이다

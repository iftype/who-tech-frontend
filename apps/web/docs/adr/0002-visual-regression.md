# 0002 스크린샷 비교를 구조 변경의 안전망으로

- 상태: 적용 (2026-10-19, #85)

## 배경

구조 개선의 첫 원칙은 "운영 기능 불변"이었다. 폴더 이동·컴포넌트 분리·스타일 정리는 테스트가 통과해도 화면이 미세하게 바뀔 수 있다(클래스 하나, 간격 하나). 사람이 눈으로 비교하면 라이트·다크와 여러 화면을 매번 다 볼 수 없다.

## 결정

주요 화면을 라이트·다크로 찍어 기준 이미지와 픽셀 비교한다(Playwright, 38장). 흔들림을 없애는 장치를 함께 둔다.

- **API 응답 녹화**: 운영 API 응답을 한 번 녹화해 `e2e/visual/fixtures`에 두고 로컬 서버(`fixture-server.mjs`)로 돌려준다. 공개 저장소라 소유자 외 개인 정보는 익명화한다(`anonymize-fixtures.mjs`)
- **시각 고정**: 서버 시각을 녹화 시각으로 고정한다(`server-preload.mjs`). "3일 전" 같은 상대 시간이 흔들리지 않는다
- **바깥 요청 차단**: fixture 서버 외 주소로 나가는 fetch를 막는다. 실수로 운영 API를 보는 빌드로 테스트하면 조용히 통과하지 않고 바로 실패한다
- **Linux 기준 이미지**: 글꼴 렌더링이 OS마다 달라서 기준 이미지는 CI(Linux)에서만 만든다. 바꿀 때는 워크플로의 `update_snapshots` 입력으로 다시 찍는다
- 필수 체크(Web visual regression)로 둬 차이가 있으면 머지할 수 없다

## 결과

- 이후 구조 PR(#86 · #87 · #88 · #91 · #92) 모두 0픽셀 차이로 머지
- 버튼 모양을 `shared/ui`로 옮길 때는 클래스 집합 테스트(`variants.test.ts`)와 스테이징·운영의 class 비교를 더해 스크린샷에 안 잡히는 상태(호버, 키보드 선택, 모바일 메뉴)도 확인했다

## 비용

- 의도한 화면 변경이 있으면 기준 이미지를 다시 찍어야 한다
- 녹화 데이터가 오래되면 실제 데이터 모양과 멀어진다. API 계약이 바뀌면 다시 녹화한다
